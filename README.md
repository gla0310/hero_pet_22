# hero pet 🐾

نظام إدارة داخلي (استقبال) لعيادة بيطرية — يعمل بالكامل **Offline** على تابلت Android (Honor Pad).

مبني بـ Flutter + Dart + SQLite (sqflite)، واجهة عربية RTL، اللون الرسمي أخضر غامق.

> ⚠️ هذا التطبيق **لا** يسجل التشخيص أو العلاج أو الأدوية أو التحاليل — فقط تنظيم الاستقبال (عملاء، أليفات، مواعيد، فندقة، إجراءات، زيارات).

---

## آخر التحديثات (أهم التعديلات على النسخة الأصلية)

- **الشاشة الرئيسية**: شريط بحث طويل بالجوال في الأعلى + جرس تذكيرات (يسار) + 3 أيقونات فقط
  (إضافة عميل / المواعيد / الفندقة)، مع **لوحة معلومات (Dashboard)** أسفل الأيقونات مباشرة تعرض:
  آخر العملاء، آخر دخولات الفندقة، آخر خروجاتها — وكل قسم له زر "عرض الكل".
- تم **حذف** شاشة "إضافة أليفة لعميل موجود" المستقلة نهائياً (البحث + ملف العميل يغطيها).
- **المواعيد**: قائمة موحّدة بكل المواعيد القادمة + إضافة/تعديل/حذف، ونوع الموعد أصبح
  اختياراً ثابتاً (تطعيم / إجراء طبي) بدل النص الحر.
- **التذكيرات**: 3 تبويبات - المواعيد القادمة، التسليمات اليوم، **متأخرون عن الخروج**.
- **الفندقة**: قسم موحّد بثلاث بطاقات (تسجيل دخول / المتواجدون حالياً / تسجيل خروج)، ونوع
  الحالة عند الدخول أصبح اختياراً واحداً (فندقة عادية / فندقة علاجية / إجراء طبي) بنفس الحقول.
  الخروج دائماً ينتهي بحالة **"تم التسليم"** موحّدة، ولا يمكن إتمامه بدون صورة عقد الاستلام.
- **ملاحظات أثناء التواجد**: من شاشة "المتواجدون حالياً"، يمكن فتح أي أليفة وإضافة/تعديل/حذف
  ملاحظات مؤرّخة دون أن يُعتبر ذلك تسجيل خروج (جدول `AdmissionNotes` جديد).
- **نظام التأخير**: أي أليفة تجاوز تاريخها المتوقع للخروج تاريخ اليوم تُعتبر **"متأخرة عن
  الخروج"** وتُميَّز بوضوح (لون أحمر) في: لوحة المعلومات، شاشة المتواجدين حالياً، وشاشة
  التذكيرات (مع عدد أيام التأخير). تختفي تلقائياً بمجرد تسجيل الخروج الفعلي.
- **ملف العميل**: أزرار إجراءات سريعة (إضافة أليفة / زيارة عيادة / موعد / تسجيل دخول فندقة)
  توفّر الوقت دون الرجوع للشاشة الرئيسية، ويعرض ملف كل أليفة الآن جميع العقود (بصور مصغّرة
  قابلة للتكبير) وجميع الملاحظات وكل المواعيد.
- **زيارة العيادة**: خيار "إضافة موعد قادم" اختياري ينشئ موعداً تلقائياً (متابعة/تطعيم/
  إجراء طبي/أخرى) يظهر مباشرة في شاشتي المواعيد والتذكيرات.
- تم تغيير الاسم الظاهر للتطبيق إلى **hero pet** (بأحرف صغيرة) في كل الواجهات.

## 1) هيكل المشروع

```
hero_pet/
  lib/
    core/            # الألوان، الثيم، الثوابت
    models/           # Client, Pet, Visit, Appointment, Reminder, Admission, AdmissionNote
    database/         # db_helper.dart (كل عمليات SQLite)
    utils/            # مساعدات: الصور، واتساب، التاريخ
    widgets/          # عناصر واجهة مشتركة
    screens/
      home_screen.dart          # الشاشة الرئيسية + لوحة المعلومات
      dashboard/                 # أقسام لوحة المعلومات وشاشات "عرض الكل"
      client/                    # إضافة عميل + ملف العميل الكامل + إجراءات سريعة
      pet/                       # إضافة أليفة + خيارات ما بعد الإضافة + ملف الأليفة
      hotel/                     # قسم الفندقة الموحّد (دخول/متواجدون/خروج/ملاحظات)
      clinic/                    # زيارة عيادة (مع خيار إضافة موعد قادم)
      appointments/              # المواعيد (قائمة موحّدة + إضافة/تعديل/حذف)
      reminders/                 # التذكيرات (مواعيد قادمة / تسليمات اليوم / متأخرون)
      backup/                    # نسخ احتياطي / استرجاع
  setup_reference/
    AndroidManifest_reference.xml   # صلاحية الكاميرا المطلوب إضافتها بعد flutter create
  pubspec.yaml
```

## 2) قاعدة البيانات (SQLite) — الإصدار 3

الجداول: `Clients, Pets, Visits, Appointments, Reminders, Admissions, AdmissionNotes`.
**رقم الجوال (`phone`) هو المفتاح الأساسي** للبحث عن العميل.

- `Clients.created_at`: أُضيف في الإصدار 3 (تاريخ إضافة العميل، يُستخدم في لوحة المعلومات).
- `AdmissionNotes`: أُضيف في الإصدار 2 (ملاحظات مؤرّخة أثناء تواجد الأليفة).
- الترقية بين الإصدارات تتم تلقائياً عبر `onUpgrade` **دون فقدان أي بيانات موجودة**.

جدول `Admissions` موحّد بين "الفندقة" و"الإجراء الطبي" عبر حقل `type`
(`hotel` أو `procedure`)، مع حقل `status` الذي يحدد حالة الأليفة:

- `طبيعي` (لا يوجد إجراء حالي)
- `موجودة في الفندقة` أو `موجودة في العيادة` (نشطة حالياً)
- `تم التسليم` (الحالة النهائية الموحّدة عند الخروج، لكل الأنواع)

"التأخر عن الخروج" **ليس** حقلاً مخزّناً — بل يُحسب مباشرة بمقارنة
`expected_exit_date` بتاريخ اليوم لأي عملية ما زالت نشطة.

## 3) طريقة تشغيل المشروع (مرة واحدة فقط)

### المتطلبات
- تثبيت [Flutter SDK](https://docs.flutter.dev/get-started/install) (قناة stable)
- تثبيت Android Studio (لأجل Android SDK + قبول التراخيص)
- جهاز Honor Pad موصول بالكمبيوتر عبر USB مع تفعيل **وضع المطور + تصحيح USB (USB Debugging)**،
  أو محاكي Android

### الخطوات

```bash
# 1) فك ضغط المشروع ثم ادخل المجلد
cd hero_pet

# 2) هذا المشروع يحتوي على كود Dart فقط (lib/ + pubspec.yaml)
#    شغّل الأمر التالي لتوليد مجلدات المنصّات (android/ios/...) تلقائياً:
flutter create .

# 3) عند التنفيذ سيسألك Flutter عن استبدال بعض الملفات، اختر "نعم" فقط
#    لملفات لم تُنشئها أنت (لن يمسّ مجلد lib/ أو pubspec.yaml الذي أنشأناه)

# 4) أضف صلاحية الكاميرا لملف android/app/src/main/AndroidManifest.xml
#    (انسخ السطرين التاليين داخل <manifest> كما هو موضح في
#    setup_reference/AndroidManifest_reference.xml):
#    <uses-permission android:name="android.permission.CAMERA" />
#    <uses-feature android:name="android.hardware.camera" android:required="false" />

# 5) نزّل الحزم
flutter pub get

# 6) تأكد أن الجهاز متصل
flutter devices

# 7) شغّل التطبيق مباشرة على الجهاز (وضع Debug للتجربة)
flutter run
```

> 💡 إذا كان الجهاز يحتوي مسبقاً على نسخة سابقة من التطبيق (قبل هذه التحديثات)،
> فسيتم ترقية قاعدة بياناته تلقائياً عند أول تشغيل دون فقدان أي بيانات (العملاء،
> الأليفات، المواعيد، سجلات الفندقة... كلها تبقى كما هي).

## 4) بناء نسخة APK نهائية جاهزة للتثبيت على Honor Pad

```bash
flutter build apk --release
```

سيظهر ملف الـ APK في المسار:

```
build/app/outputs/flutter-apk/app-release.apk
```

انسخ هذا الملف إلى تابلت Honor Pad (عبر USB أو بطاقة SD أو Bluetooth)، ثم:

1. من إعدادات الجهاز، فعّل **"السماح بتثبيت تطبيقات من مصادر غير معروفة"**
   (Install unknown apps) لتطبيق مدير الملفات الذي ستستخدمه لفتح الـ APK.
2. افتح ملف `app-release.apk` من مدير الملفات واضغط تثبيت.

> 💡 إذا أردت تصغير حجم الملف حسب معمارية المعالج فقط، استخدم:
> `flutter build apk --release --split-per-abi`

## 5) ملاحظات تقنية مهمة

- **الصور (عقود/صور الأليفات)**: تُحفظ داخل مجلد بيانات التطبيق الخاص
  (`ApplicationDocumentsDirectory/images/`) ويُحفظ **المسار فقط** في SQLite — Offline بالكامل.
- **قاعدة البيانات**: ملف واحد `hero_pet.db` داخل نفس مجلد بيانات التطبيق.
- **النسخ الاحتياطي**: من أيقونة أعلى يمين الشاشة الرئيسية. النسخة الحالية تنسخ ملف
  قاعدة البيانات فقط، ولا تشمل مجلد الصور تلقائياً؛ يمكن تطويرها لاحقاً لضغط (zip) مجلد
  `images/` مع الملف إن رغبتم.
- **واتساب**: زر "إرسال عبر واتساب" يفتح المحادثة مع رسالة جاهزة، والموظف يضغط "إرسال"
  بنفسه (لا يوجد إرسال تلقائي). الرابط `whatsapp://send` يفتح تلقائياً أي نسخة مثبتة
  (عادية أو Business) — إن كان التطبيقان مثبتين معاً فنظام Android هو من يعرض قائمة
  الاختيار (سلوك النظام، لا يمكن للتطبيق فرض أحدهما).
- **قابلية التطوير**: فصل واضح بين `models`، `database`، و`screens` لتسهيل إضافة ميزات
  مستقبلاً (طباعة، تصدير Excel، ربط سحابي عند توفر إنترنت لاحقاً... إلخ).

---

## 6) لماذا لم يُرفق ملف APK جاهز مباشرة؟

توليد APK يتطلب Flutter SDK + Android SDK وأدوات بناء (Gradle) مع اتصال إنترنت
لتنزيل الاعتماديات — وهذه غير متوفرة في بيئة التوليد الحالية. لذلك تم تجهيز **كل
الكود المصدري كاملاً وجاهزاً للتشغيل والبناء مباشرة** بأمر واحد (`flutter build apk --release`)
بمجرد تثبيت Flutter على أي جهاز كمبيوتر، كما هو موضح في الخطوات أعلاه.
